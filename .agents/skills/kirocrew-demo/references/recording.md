# Capture and update the controls walkthrough

Read [docs/MANAGED-DEMO.md](../../../../docs/MANAGED-DEMO.md), [docs/HOST-CONTROL-SCENARIOS.md](../../../../docs/HOST-CONTROL-SCENARIOS.md), and the chosen scenario's current preflight before running it. Use [docs/NATIVE-CLIENT-DEMO.md](../../../../docs/NATIVE-CLIENT-DEMO.md) for the earlier native controls and [docs/RECORDING.md](../../../../docs/RECORDING.md) for the capture workflow. The separate synthetic harness is useful for rehearsal and never establishes native enforcement.

Check native dependencies with `scripts/doctor.py --feature native`. Permission observations describe the checking process; inspect a fresh screenshot and a visible UI update from the actual recorder before starting. Stop a capture if the window freezes, the Mac locks, or the screenshot disagrees with current UI state. Do not build a demonstration from stale window imagery.

Finish all required Gateway restarts before preparing the take. Create a persistent dedicated native session, send `Reply READY without calling any tools.`, and wait until it is idle. Then start the observer against that exact saved session; a transient or pre-restart slot can make the collected interval refer to the wrong conversation. Keep the READY exchange outside the control take.

For macOS `screencapture` video, select a bounded duration with `-V` and let it end normally. In this workflow, sending SIGINT discarded the movie. Do not use Ctrl-C as the normal stop method. After natural completion, verify that the MOV exists and that ffprobe can read its duration before trimming or making a new capture.

A control take should show a real user request, any native approval actually required, and the resulting server decision. Use the prepared harmless fixtures and existing tagged demo resources. Keep normal approval enabled; do not accept an approval through a private API. Capture the relevant conversation/SEL/MCP receipt afterward and check that the action reached the claimed boundary. Retain raw footage and full private observers only in ignored locations; export reviewed clips and sanitized receipts.

For managed MCP governance, show the normal user's **Connections → MCP Servers** view, the server/tool list and available local toggles, then the managed policy display and an actual denied request. The frozen UI may show a centrally denied tool as locally enabled: explain that the toggle controls local availability while the server policy governs execution. Do not invent a governance lock badge or enterprise registry. Show an allowed control alongside the denial when it helps establish that the connection works.

The [recorded managed denial](../../../../evidence/enterprise-managed/20260913/native-managed-ui4-verification.json) joins the exact native blocked row to a policy-layer security event and a completed MCP-service interval with no arrival. Its permitted read belongs to an earlier take; do not describe that read as filmed in the denial clip. Use new native and server receipts for each new recording. Keep [host verification](../../../../scripts/verify-managed-host.py) separate from exact-tool enforcement and media acceptance.

Tour the admin panel separately with actual screenshots: effective policy source, MCP connections, session details, security events, client/server telemetry and collection timestamps. State what the UI actually reports. Seatbelt applies to execution on macOS; the EC2 runtime uses the supported Linux isolation path. A parsed or displayed setting alone does not establish enforcement.

Process reviewed cuts with `scripts/demo-clips.py MANIFEST --check`, then encode to a fresh output using its `--output` option. FFmpeg transforms real footage; it does not generate product evidence. Mark whether a clip covers request-to-result, approval-to-result, or result inspection. Update findings, tour, notes and the deck from the same verified outcomes, and preserve one endpoint-control enclosure in the diagram. Use the presentation recipe for a derivative export and validate navigation, playable clips, seek cues and asset isolation before shipping.
